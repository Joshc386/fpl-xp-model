## Process that worked, and lessons (new this session)
1. **Usage limits:** three agents in parallel hit the 5-hour limit four times.
   A stopped agent resumes with `SendMessage` to its name, and its work is
   saved. Prefer two at a time.
2. **Parallel agents in one checkout:**
   - give each its own `COVERAGE_FILE`;
   - tell each which failures come from another agent's half-built work, such
     as `load_as_of` raising `KeyError` mid-build;
   - reviewers mutate only in scratch copies, with `PYTHONPATH=<copy>/src`.
3. **Committing my entries alone in a shared file:**
   - for `docs/decisions.md`: `git show HEAD:docs/decisions.md` plus my entry,
     then `git hash-object -w --path=...` and
     `git update-index --cacheinfo`;
   - for one hunk of a shared config: `git apply --cached --unidiff-zero`;
   - check `git diff --cached` every time.
4. **A contract commit makes `test_schema.py` fail until its code lands.**
   Don't push contract commits before the code.
5. **Reviews:** a first review with at least 10 mutants, then a focused
   re-review that skips the full suite. Run one final full suite before
   committing.
6. **Never put the modeller's findings in a `main - ...` entry** or in
   `known_gaps.md`. The validator reads both.
7. **Recheck agents' headline numbers from the raw files before citing them.**
   This session it confirmed the 157 matches without substitution times, the
   blank shooters, the 2025/26 git history and the bad `start_min` rows.
